## Overview

The Appwrite Node.js SDK supports two authentication modes depending on who is performing the operation:

| Mode | Method | Use case |
|---|---|---|
| API key | `setKey()` | Server-to-server operations with admin privileges |
| JWT | `setJWT()` | Acting on behalf of a logged-in user |
| Session | `setSession()` | Acting on behalf of a user with a session secret |

`setProject()` and `setEndpoint()` are always required regardless of auth mode.

---

## Required configuration

### setProject()

Every request must be associated with an Appwrite project. Call `setProject()` with your project ID before making any requests.

```typescript
client.setProject('<YOUR_PROJECT_ID>');
```

Find your project ID in the Appwrite Console under **Settings → Overview**.

### setEndpoint()

The SDK defaults to `https://cloud.appwrite.io/v1` (Appwrite Cloud). Override this for self-hosted instances:

```typescript
client.setEndpoint('https://appwrite.example.com/v1');
```

The endpoint must start with `http://` or `https://` — the SDK throws an `AppwriteException` if the value is invalid.

## API key authentication

Use an API key for server-side operations that require admin-level access, such as creating users, managing databases, or sending messages.

### setKey()

```typescript
setKey(value: string): this
```

Sets the `X-Appwrite-Key` request header on every subsequent request.

```typescript
import { Client } from 'node-appwrite';

const client = new Client()
    .setEndpoint('https://cloud.appwrite.io/v1')
    .setProject('<YOUR_PROJECT_ID>')
    .setKey('<YOUR_API_KEY>');
```

### Creating an API key

<Steps>
  <Step title="Open the Appwrite Console">
    Go to your project in [cloud.appwrite.io](https://cloud.appwrite.io) or your self-hosted instance.
  </Step>
  <Step title="Navigate to API Keys">
    In the left sidebar, click **Settings → API Keys**.
  </Step>
  <Step title="Create a new key">
    Click **Create API key**, give it a name, and select the scopes your server needs (e.g. `users.read`, `users.write`, `databases.read`).
  </Step>
  <Step title="Copy the secret">
    Copy the generated secret and store it in your environment configuration. You will not be able to view it again.
  </Step>
</Steps>

<Warning>
  Never expose your API key in client-side code, public repositories, or version control. It grants admin-level access to your project. Store it as an environment variable and read it at runtime.
</Warning>

```typescript
// Read from environment — never hardcode secrets
const client = new Client()
    .setEndpoint(process.env.APPWRITE_ENDPOINT!)
    .setProject(process.env.APPWRITE_PROJECT_ID!)
    .setKey(process.env.APPWRITE_API_KEY!);
```

## JWT authentication

Use a JWT when you want the SDK to act on behalf of a specific user. The JWT is generated by Appwrite after the user authenticates (for example via the web SDK), and it encodes the user's identity and permissions.

### setJWT()

```typescript
setJWT(value: string): this
```

Sets the `X-Appwrite-JWT` request header. Requests are scoped to the permissions of the user who owns the JWT.

```typescript
import { Client, Databases } from 'node-appwrite';

const client = new Client()
    .setEndpoint('https://cloud.appwrite.io/v1')
    .setProject('<YOUR_PROJECT_ID>')
    .setJWT('<USER_JWT>');                // Obtained from the client-side web SDK

const databases = new Databases(client);
// Requests run with the permissions of the JWT's user
```

<Note>
  JWTs are short-lived. Generate them fresh on each request or cache them until they expire. Do not use an API key and a JWT at the same time — the API key takes precedence.
</Note>

## Session authentication

Use a session secret string when you have a user's session token (e.g. forwarded from a client request) and want the server to act on their behalf.

### setSession()

```typescript
setSession(value: string): this
```

Sets the `X-Appwrite-Session` request header.

```typescript
import { Client, Account } from 'node-appwrite';

const client = new Client()
    .setEndpoint('https://cloud.appwrite.io/v1')
    .setProject('<YOUR_PROJECT_ID>')
    .setSession('<USER_SESSION_SECRET>');

const account = new Account(client);
const user = await account.get(); // Returns the session owner
```

## Self-signed SSL certificates

When running a self-hosted Appwrite instance in development with a self-signed SSL certificate, call `setSelfSigned(true)` to disable certificate verification.

### setSelfSigned()

```typescript
setSelfSigned(selfSigned: boolean): this
```

```typescript
const client = new Client()
    .setEndpoint('https://localhost/v1')
    .setProject('<YOUR_PROJECT_ID>')
    .setKey('<YOUR_API_KEY>')
    .setSelfSigned(true); // Dev only — never use in production
```

<Warning>
  `setSelfSigned(true)` disables TLS certificate verification. Use it only in local development. It is not supported in edge runtimes.
</Warning>

## Full configuration example

```typescript
import { Client, Users } from 'node-appwrite';

const client = new Client()
    .setEndpoint(process.env.APPWRITE_ENDPOINT ?? 'https://cloud.appwrite.io/v1')
    .setProject(process.env.APPWRITE_PROJECT_ID!)
    .setKey(process.env.APPWRITE_API_KEY!);

// All services share the same configured client
const users = new Users(client);
```

## Security best practices

- Store your API key in environment variables, not in source code.
- Grant only the scopes your server actually needs — avoid using a key with all scopes.
- Rotate API keys regularly and immediately if they are compromised.
- Use JWTs or sessions (not API keys) when acting on behalf of a user.
- Never use `setSelfSigned(true)` in a production environment.
